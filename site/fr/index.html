Les port-forwards Kubernetes dans la barre des menus.

Créez un Forward une fois, puis activez-le d'un interrupteur. Visez un Service et Kubeport suit les pods : après un rollout ou un crash, la connexion suivante vers localhost atteint un pod Ready.

Kubeport 0.4.0

Essayez : actionnez un interrupteur.

Ou ajoutez un Forward.

Un rollout ne coupe plus votre connexion

kubectl port-forward svc/… choisit un pod et s'arrête avec lui. Kubeport surveille le Service : quand ce pod cesse d'être Ready, les nouvelles connexions vont vers un autre pod Ready. Les connexions déjà ouvertes vers l'ancien pod se ferment.

Un Forward oublié s'éteint tout seul

Sur une nouvelle installation, un Forward sans connexion ouverte pendant une heure passe Inactif et rend son port. Une nouvelle connexion remet le compte à rebours à zéro. Changez ce délai dans les Réglages ou pour un seul Forward, ou choisissez Jamais.

Choisissez dans votre cluster, puis activez

Kubeport vit dans la barre des menus, comme le menu Wi-Fi de macOS. Pas d'icône dans le Dock, pas de fenêtre à gérer.

Création guidée
Choisissez le Contexte, le namespace, le Service ou le Pod et le port dans des listes lues depuis votre cluster. Kubeport remplit le port local et le nom.
Un interrupteur par Forward
Activez ou désactivez un Forward depuis sa ligne. L'interrupteur général coupe tous les Forwards, puis rétablit les mêmes. Les Forwards actifs à la fermeture reviennent au lancement suivant.

Caractéristiques

Kubeconfig
N'importe quel kubeconfig, y compris les plugins d'authentification exec pour EKS, GKE, AKS et kubelogin. Pas besoin de kubectl.
Langues

Installation

Avec Homebrew

Terminal
brew tap deki-lab/tap
brew trust deki-lab/tap
brew install --cask deki-lab/tap/kubeport

brew trust est là parce que Homebrew 7 et suivants demande d'approuver les taps tiers.

Ou téléchargez l'application

Téléchargez le .dmg depuis la dernière version et glissez Kubeport dans Applications. Kubeport demande macOS 14 ou plus récent, sur un Mac Apple silicon ou Intel.

Premier lancement

Kubeport n'est pas encore signé avec un Developer ID Apple : macOS le bloque la première fois.

  1. Ouvrez Kubeport une fois, puis fermez l'alerte.
  2. Allez dans Réglages Système › Confidentialité et sécurité.
  3. Cliquez sur Ouvrir quand même à côté de Kubeport, puis confirmez.

Ou retirez la marque de téléchargement depuis le Terminal, avant d'ouvrir Kubeport pour la première fois :

Terminal
xattr -dr com.apple.quarantine /Applications/Kubeport.app

Ne l'exécutez que sur un Kubeport installé depuis la page des versions ou le tap Homebrew.

Seul votre compte peut utiliser un port de Kubeport

Kubeport ouvre le même genre de tunnel que kubectl port-forward, avec les mêmes limites.

Votre compte seulement
Le port local vérifie qui se connecte. Les connexions d'un autre compte ou de root sont fermées aussitôt.
Loopback seulement
Les Forwards écoutent sur 127.0.0.1, et sur ::1 quand votre Mac a l'IPv6. Un Forward Actif garde son port jusqu'à ce que vous le désactiviez, même pendant une reconnexion : aucun autre processus ne peut le prendre.
Pas de secret divulgué
Quand un plugin d'authentification du kubeconfig échoue, Kubeport n'affiche que son code de sortie, jamais ses arguments, son environnement ni sa sortie.

Comme avec kubectl port-forward, une page web ouverte dans votre navigateur peut atteindre les ports localhost d'un Forward par DNS rebinding. Lisez les notes de sécurité pour savoir comment protéger un service HTTP exposé par un Forward.
